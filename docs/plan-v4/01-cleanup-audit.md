# Plan-v4 Week 1 — Cleanup audit

> One-screen audit of files that may be obsolete given the Plan-v4 narrative shift. **No deletions performed.** Every row below is a proposal for the architect to review and action separately, ideally as single-purpose follow-up commits.

Scope of this audit: the public monorepo at the top level, `docs/`, `scripts/`, and the in-tree project directories. The `files/` directory is gitignored (working downloads, not in repo) and not in scope. The `bls-platform-private` repo is also out of scope.

## Notes on what is **not** in the audit

- **`files/` directory** — gitignored. Local-only download/scratch space. Contains earlier-version master plans (`BLS-master-plan-v3.md`, `bls-master-plan/`) that are working artefacts from the Plan-v3 era, not committed history. No action required.
- **`PHASE-2-HANDOFF.md`** — gitignored. Session-continuity doc; deliberately ignored per the architect's working pattern (matches `BLS-STATUS.md`). Out of scope for cleanup.
- **`docs/plan-v4/orchestration-prompts.md`** — newly gitignored in this PR (was previously caught by the broader `docs/plan-v4/` ignore). The orchestration prompts are local-only weekly source-of-truth; the Plan-v4 directory itself is now committed so the operating doc, this audit, and the concept→tool mapping can ship publicly.
- **ADR-002, ADR-003, ADR-005, ADR-006 and `02-k3s-platform/docs/adr/ADR-004-…`** — all current, all referenced from PHASE-2-HANDOFF.md or BLS-STATUS.md. None obsolete.
- **`docs/runbooks/sealed-secrets-controller.md`** — current, load-bearing for WU-1 closure. Not obsolete.

## Failure-mode flag

None of the proposed actions in this audit would lose unrecoverable context. The two largest blobs (`04-llm-gateway/README.md`, `docs/BLS-Platform-Operations-Guide.docx`) have explicit "port the content first" preconditions. The `.terraform/` cache directory contains no human-authored content. Everything else is "keep" or "move."
