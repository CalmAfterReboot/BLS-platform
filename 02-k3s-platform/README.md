- 6-core Xeon, 128 GB RAM
- Storage: `local-lvm` (LVM thin pool)
- Network: VLAN-aware bridge (`VLAN`), tagged VLAN 200

**Control Plane Nodes** — etcd quorum, k3s API server

|---|---|---|---|---|---|
| k3s-control-01 | 201 | 192.168.200.10 | 2 | 4 GB | 32 GB |
| k3s-control-02 | 202 | 192.168.200.11 | 2 | 4 GB | 32 GB |
| k3s-control-03 | 203 | 192.168.200.12 | 2 | 4 GB | 32 GB |

**Worker Nodes** — workload scheduling

| Name | VM ID | IP | vCPU | RAM | Disk |
|---|---|---|---|---|---|
| k3s-worker-01 | 204 | 192.168.200.20 | 2 | 16 GB | 80 GB |
| k3s-worker-02 | 205 | 192.168.200.21 | 2 | 16 GB | 80 GB |

**All VMs:** CPU type `host` (passthrough), CPU units `512`, `qemu-guest-agent` enabled, `on_boot = true`, `discard = on` (LVM thin provisioning), cloud-init user `ansible`.

### Network Architecture

```
Management Network ──► pfSense firewall
                            │
                   inter-VLAN routing
                            │
                       VLAN 200 (192.168.200.0/24)
                            │
                  Proxmox VLAN-aware bridge (VLAN)
                    │               │
             Control Plane     Worker Nodes
             .10 .11 .12       .20 .21
```

- **Gateway / DNS:** 192.168.200.1 (pfSense with unbound)
- **Secondary DNS:** 1.1.1.1
- pfSense manages inter-VLAN routing between the management network and VLAN 200
- All k3s nodes are isolated on VLAN 200; inbound access only on explicitly allowed ports

## Phase 1 — Cloud-Init Template (Proxmox Host)

Run these commands directly on the Proxmox host as root. This creates VM ID 9000 — the Ubuntu 24.04 cloud-init template that all five nodes clone from.

### 1.1 Download Ubuntu Cloud Image

```bash
cd /var/lib/vz/template/iso

wget https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
```

### 1.2 Inject QEMU Guest Agent

The `bpg/proxmox` provider requires `qemu-guest-agent` to retrieve VM IPs post-boot. Install it into the image before creating the template:

```bash
virt-customize \
  -a noble-server-cloudimg-amd64.img \
  --install qemu-guest-agent \
  --truncate /etc/machine-id
```

> **Why truncate `/etc/machine-id`?** Each cloned VM must generate its own unique machine-id on first boot. If the template has a populated `machine-id`, all clones share the same DUID, causing DHCP lease conflicts and preventing each VM from acquiring its own IP — even with static cloud-init configuration.

### 1.3 Create the Template VM

```bash
# Create VM shell
qm create 9000 \
  --name ubuntu-2404-cloud \
  --memory 2048 \
  --cores 2 \
  --net0 virtio,bridge=VLAN

# Import the cloud image as a disk into local-lvm
qm importdisk 9000 noble-server-cloudimg-amd64.img local-lvm

# Attach disk as scsi0 with discard support
qm set 9000 \
  --scsihw virtio-scsi-pci \
  --scsi0 local-lvm:vm-9000-disk-0,discard=on

# Attach cloud-init drive
qm set 9000 --ide2 local-lvm:cloudinit

# Set boot order
qm set 9000 --boot c --bootdisk scsi0

# Enable serial console (cloud-init requirement)
qm set 9000 --serial0 socket --vga serial0

# Convert to template (irreversible)
qm template 9000
```

### 1.4 Verify

```bash
qm list | grep 9000
# Expected: 9000  ubuntu-2404-cloud  template  ...
```

## Phase 2 — Terraform Provisioning

### Key Design Decisions

| Decision | Rationale |
|---|---|
| `bpg/proxmox` pinned at `0.66.3` | Breaking changes in newer versions; pin prevents silent drift |
| `cpu.type = "host"` | Full CPU passthrough — exposes host flags required by k3s eBPF and kube-proxy |
| `cpu.units = 512` | Reserves Proxmox scheduler priority for k3s nodes vs management VMs |
| `discard = "on"` | Enables TRIM on LVM thin pool — prevents over-provisioning on `local-lvm` |
| `for_each` over locals maps | DRY VM definitions; adding a node is a single locals entry |
| Outputs sourced from locals | `control_plane_ips` and `worker_ips` are available at `plan` time, not just after `apply` |
| Azure remote state | Shared, locked state enables safe multi-operator workflows |
| `insecure = true` on provider | Proxmox uses a self-signed certificate on the API endpoint |

### 2.1 Initialise

```bash
cd terraform/
terraform init
```

Expected output: `Successfully configured the backend "azurerm"!`

### 2.2 Plan

```bash
terraform plan -out=k3s.tfplan
```

Verify the plan shows **5 to add, 0 to change, 0 to destroy** and that each VM has the correct IP, memory, and disk size before continuing.

### 2.3 Apply

```bash
terraform apply k3s.tfplan
```

All five VMs clone from template 9000, resize their disks, and boot with cloud-init static IP configuration. The `ansible` user and SSH public key are created on first boot.

## Phase 4 — Node Hardening

The `node-hardening` role from [BLS Project 1 (Landing Zone)](../ansible/roles/node-hardening) is reused here with k3s-compatible defaults.

### 4.1 Run the Playbook

```bash
cd ansible/

# Verify connectivity first
ansible k3s_cluster -m ping -i inventory/hosts.yml

# Run full hardening
ansible-playbook harden.yml -i inventory/hosts.yml
```

### 4.2 Playbook Structure

```yaml
# harden.yml
- name: Harden all k3s nodes
  hosts: k3s_cluster
  become: true
  roles:
    - node-hardening
```

The role runs eight task files in order:

| Task file | What it does |
|---|---|
| `packages.yml` | Waits for apt lock; removes legacy packages; installs hardening tools; enables unattended security upgrades |
| `ssh.yml` | Deploys hardened `sshd_config`; removes DH moduli < 3072 bits; validates config before reload |
| `ufw.yml` | Default deny inbound/routed; allow outbound; opens k3s-required ports |
| `sysctl.yml` | Deploys `/etc/sysctl.d/99-bls-hardening.conf` with kernel hardening + k3s requirements |
| `limits.yml` | Sets 65536 nofile/nproc limits via PAM; ensures `pam_limits.so` active |
| `fail2ban.yml` | Deploys `jail.local`; UFW ban backend; SSH jail enabled |
| `auditd.yml` | Installs auditd; deploys rules for privilege escalation, identity, SSH config, cron |
| `ntp.yml` | Installs chrony; deploys UK NTP pool config; disables `systemd-timesyncd` |

### 4.3 Run Selective Tasks with Tags

```bash
# SSH hardening only
ansible-playbook harden.yml -i inventory/hosts.yml --tags ssh

# UFW + sysctl only
ansible-playbook harden.yml -i inventory/hosts.yml --tags ufw,sysctl

# Dry run (check mode)
ansible-playbook harden.yml -i inventory/hosts.yml --check --diff
```

## Security Hardening Reference

### SSH (`/etc/ssh/sshd_config`)

```
PermitRootLogin         no
PasswordAuthentication  no
PubkeyAuthentication    yes
AllowUsers              ansible
MaxAuthTries            3
LoginGraceTime          30
ClientAliveInterval     300
ClientAliveCountMax     2
X11Forwarding           no
AllowTcpForwarding      no
AllowAgentForwarding    no
```

**Algorithms (modern-only, OpenSSH 9.x):**

```
KexAlgorithms    curve25519-sha256, curve25519-sha256@libssh.org,
                 diffie-hellman-group16-sha512, diffie-hellman-group18-sha512
Ciphers          chacha20-poly1305@openssh.com, aes256-gcm@openssh.com,
                 aes128-gcm@openssh.com
MACs             hmac-sha2-512-etm@openssh.com, hmac-sha2-256-etm@openssh.com
HostKeyAlgorithms ssh-ed25519, ssh-ed25519-cert-v01@openssh.com,
                  rsa-sha2-512, rsa-sha2-256
```

Diffie-Hellman moduli smaller than 3072 bits are stripped from `/etc/ssh/moduli`. A sentinel file at `/etc/ssh/.moduli_hardened` makes the task idempotent.

### UFW Firewall

Default policy: **deny inbound, deny routed, allow outbound.**

| Port | Protocol | Service |
|---|---|---|
| 22 | TCP | SSH |
| 6443 | TCP | k3s API server |
| 2379 | TCP | etcd client |
| 2380 | TCP | etcd peer replication |
| 10250 | TCP | kubelet metrics |
| 8472 | UDP | Flannel VXLAN overlay |
| 51820 | UDP | WireGuard (k3s optional) |

### Kernel (`/etc/sysctl.d/99-bls-hardening.conf`)

```ini
net.ipv4.ip_forward                    = 1   # Required for k3s
net.bridge.bridge-nf-call-iptables     = 1   # Required for k3s
net.bridge.bridge-nf-call-ip6tables    = 1   # Required for k3s
net.ipv4.tcp_syncookies                = 1   # SYN flood protection
net.ipv4.conf.all.send_redirects       = 0
net.ipv4.conf.default.send_redirects   = 0
net.ipv4.conf.all.accept_redirects     = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv4.conf.all.log_martians         = 1
kernel.dmesg_restrict                  = 1
kernel.kptr_restrict                   = 2
```

### fail2ban (`/etc/fail2ban/jail.local`)

```ini
[DEFAULT]
bantime   = 3600        # 1 hour
findtime  = 600         # 10-minute window
maxretry  = 5
backend   = systemd
banaction = ufw         # Bans via UFW, not iptables directly

[sshd]
enabled = true
```

### auditd (`/etc/audit/rules.d/99-bls-hardening.rules`)

Monitors: privilege escalation (`setuid`/`setgid`), identity files (`passwd`, `group`, `shadow`, `sudoers`), SSH config, cron, login records. Rules locked with `-e 2` (immutable until reboot).

### PAM Limits (`/etc/security/limits.d/99-bls-hardening.conf`)

```
* soft nofile 65536
* hard nofile 65536
* soft nproc  65536
* hard nproc  65536
```

Required for k3s and container workloads that open large numbers of file descriptors.

### NTP (`/etc/chrony/chrony.conf`)

UK NTP pool (`0-3.uk.pool.ntp.org`), `systemd-timesyncd` disabled to avoid conflicts. Chrony configured with `makestep 1.0 3` to handle large initial clock drift on fresh VMs.

## Troubleshooting Log

Issues encountered during Phase 4 and their resolutions. Documented here for reproducibility and future reference.

---

### Issue 1 — `packages_remove` / `packages_install` Undefined

**Symptom:** Role failed immediately on the first package task with `variable is undefined`.

**Cause:** The variables were referenced in the task files but had no entry in `defaults/main.yml`.

**Fix:** Added both variables to `defaults/main.yml` with appropriate values for k3s nodes.

---

### Issue 2 — dpkg Lock Contention on Fresh VMs

**Symptom:** `ansible.builtin.apt` blocked indefinitely; `dpkg` returned a lock error.

**Cause:** Ubuntu 24.04 cloud-init runs `apt-get` in the background during first boot (unattended-upgrades and snap updates). Ansible arrived before this process completed.

**Fix:** Added a wait task at the top of `packages.yml` using `fuser` to poll until the lock is released:

```yaml
- name: Wait for apt lock to be released
  ansible.builtin.shell: |
    while fuser /var/lib/dpkg/lock-frontend >/dev/null 2>&1; do
      sleep 5
    done
  changed_when: false
  timeout: 300
```

---

### Issue 3 — DNS Resolution Failure on All Nodes

**Symptom:** `Temporary failure resolving 'archive.ubuntu.com'` on all five nodes simultaneously during `apt update`.

**Cause:** A stale NAT port-forward rule in pfSense was redirecting **all traffic destined for the gateway IP** (including DNS queries to unbound on port 53) to an external IP. The DNS queries never reached the local unbound resolver.

**Diagnosis path:**
1. Confirmed unbound was running and listening on wildcard (`ss -ulnp | grep 53`)
2. Confirmed access-control allowed the VLAN 200 subnet in `unbound.conf`
3. Ran `tcpdump` on the pfSense VLAN interface — DNS queries arriving but no replies
4. Inspected `config.xml` — found a NAT rule with destination `192.168.200.1/32` redirecting all ports

**Fix:** Removed the offending NAT rule from pfSense's **Firewall → NAT → Port Forward**, then reloaded the ruleset:

```bash
# On pfSense shell
pfctl -F nat
/etc/rc.filter_configure
```

**Lesson:** When DNS fails on a subnet where the resolver is definitely running, check pfSense NAT rules before spending time on resolver configuration. A NAT rule matching the resolver's own IP will silently intercept queries before they reach unbound, regardless of access-control settings.

---

### Issue 4 — Multiple Undefined Role Variables

**Symptom:** Several tasks failed with `variable is undefined` at different points in the run:

- `ssh_permit_root_login`, `ssh_pubkey_authentication`, `ssh_allow_users`
- `ssh_login_grace_time`, `ssh_client_alive_interval`, `ssh_client_alive_count_max`
- `ufw_allowed_ports` (missing `comment` field on initial definition)
- `sysctl_settings` (defined as a list; template iterates `.items()` expecting a dict)
- `limits_settings`, `fail2ban_ignoreip`, `ntp_servers`, `auditd_rules_dir`

**Cause:** The role templates and task files expected these variables, but `defaults/main.yml` was incomplete. The `sysctl_settings` format mismatch (list vs dict) caused a template rendering error even when the variable existed.

**Fix:** Added all missing variables to `defaults/main.yml` with k3s-compatible values. Changed `sysctl_settings` from a list of `{name, value}` dicts to a flat key/value dict to match `{% for key, value in sysctl_settings.items() %}` in the template.

**Note on `ip_forward`:** `net.ipv4.ip_forward = 1` is intentionally set (not a hardening regression). k3s requires IP forwarding for pod-to-pod and pod-to-service routing. Without it, the control plane starts but networking is broken.

---

### Issue 5 — auditd and chrony Not Installed

**Symptom:** Tasks in `auditd.yml` and `ntp.yml` failed with *"Destination directory does not exist"* when deploying rules/config files.

**Cause:** The original role assumed `auditd` and `chrony` were pre-installed on the base image. The Ubuntu 24.04 cloud image does not include either by default.

**Fix:** Added explicit install tasks at the top of each file:

```yaml
# auditd.yml
- name: Install auditd
  ansible.builtin.apt:
    name: auditd
    state: present

- name: Ensure auditd rules directory exists
  ansible.builtin.file:
    path: "{{ auditd_rules_dir }}"
    state: directory
    owner: root
    group: root
    mode: "0750"
```

```yaml
# ntp.yml
- name: Install chrony
  ansible.builtin.apt:
    name: chrony
    state: present

- name: Ensure chrony config directory exists
  ansible.builtin.file:
    path: /etc/chrony
    state: directory
```

### Join Control Planes 02 and 03

Join **sequentially** (not in parallel) to avoid split-brain during initial etcd cluster formation — each node must confirm membership before the next joins.

```bash
# On k3s-control-02
curl -sfL https://get.k3s.io | sh -s - server \
  --server https://192.168.200.10:6443 \
  --token <TOKEN_FROM_CONTROL_01> \
  --node-ip 192.168.200.11

# Wait for control-02 to show Ready, then on k3s-control-03
curl -sfL https://get.k3s.io | sh -s - server \
  --server https://192.168.200.10:6443 \

  --node-ip 192.168.200.12
```
